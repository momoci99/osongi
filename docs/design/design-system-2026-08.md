# 디자인 시스템 — 표면 계단과 색 재조율 (2026-08-13)

다크 테마가 밋밋하다는 지적에서 출발. 감각의 문제가 아니라 토큰 구조의 문제였다.

## 1. 진단

### 1-1. 표면 계단이 없다 (가장 큰 원인)

| 쌍 | 이전 명암비 |
|---|---|
| paper / background | **1.10** |
| border / paper | **1.10** |
| border / background | 1.22 |

배경(`#171412`)·카드(`#211E1A`)·테두리(`#2C2520`)가 사실상 같은 색이라
카드가 뜨지 않고 경계가 보이지 않았다. `MuiPaper.backgroundImage: none` 으로
MUI elevation 오버레이까지 껐는데 대체 계단을 만들지 않아 계층이 0이었다.

### 1-2. 갈색이 갈색으로 안 읽힌다

`#171412` = H24 **S12%** L8%. 채도 12%는 거의 무채색이다.
소나무·흙 색을 의도했지만 눈에는 어두운 회색으로 보였다.

### 1-3. 초록이 팔레트에 속하지 않는다

`primary #22C55E` = H142 **S71%** — Tailwind `green-500` 원본. 배경 H24와
hue 118° 차이라 조화가 아니라 튀는 스티커였다. 채도 71%는 침엽수가 아니라 형광 민트.

### 1-4. 강조색이 없다

`accent === up === #FBBF24`. 같은 색이 브랜드 강조와 상승 지표를 겸해
실질적인 강조 색이 없었다. `secondary` 는 앱 어디에서도 쓰이지 않았다.

### 1-5. 라이트 계단이 뒤집혀 있다

바닥 `#FAFAF9` 가 카드 `#F7F6F4` 보다 **밝았다**. 라이트에서 카드는 바닥보다
밝아야 떠 보인다. 다크와 같은 원인으로 라이트도 평평했다.

## 2. 적용

### 표면 3단 + 테두리가 만드는 계층

다크 저휘도 구간에서는 WCAG 명암비가 압축돼 배경끼리의 수치를 올리는 데 한계가 있다
(L7 → L12를 줘도 1.14). 그래서 **계층은 테두리가 만든다**.

| 토큰 | 다크 | 라이트 | 용도 |
|---|---|---|---|
| `surface.base` | `#110E0C` | `#F8F7F6` | 페이지 바닥 |
| `surface.raised` | `#211B18` | `#FFFFFF` | 카드·패널 |
| `surface.overlay` | `#302A24` | `#FFFFFF` | 팝오버·툴팁·선택된 컨트롤 |
| `surface.border` | `#453D35` | `#E6E3E0` | 기본 경계선 |
| `surface.borderStrong` | `#5D544B` | `#D1CCC7` | 강조 경계선 |

border/raised 명암비 **1.10 → 1.60**. `background.default`·`background.paper`·
`divider` 는 모두 이 토큰을 참조하므로 기존 컴포넌트가 자동으로 따라온다.

### 색 재조율

- 배경 갈색 채도 **12% → 16~18%**, hue 26~28로 통일 → 갈색이 갈색으로 읽힌다
- primary **H142 S71% → H150 S46%** (`#4CBD85`) → 침엽수 초록. 갈색 배경과 같은 화면에서 튀지 않는다
- accent 를 `up` 에서 분리해 송이 갓 적갈색 **H16** (`#D36B45`) 으로 독립
- `text.disabled` 를 3단계 텍스트로 신설 → `secondary` 에 `opacity 0.8` 을 겹쳐 쓰던 자리의 대비 하락(3.4) 해소
- `error`·`warning`·`success`·`info` 를 팔레트 토큰에서 파생 → MUI 기본 색이 섞이지 않는다

**accent 의 제약**: 경북 지역색이 H28이라 accent 를 지역 도트·막대 근처에서 쓰면
지역색으로 오독된다. H16에 두었지만 인접 사용은 피한다.

### 표면 계단을 실제로 소비하게

토큰만 바꾸면 쓰는 곳이 없어 화면은 그대로다. 계단을 소비하는 자리를 함께 정리했다.

- **조합 랭크 리스트를 패널로** — 같은 페이지의 등급표는 카드 위에 있는데 목록만
  맨바닥에 떠 있어 두 데이터 블록의 격이 어긋났다. 목록을 `raised` 패널로 감싸고
  열 머리글은 `base` 로 한 단 낮춰 표의 지붕처럼 읽히게 했다
- `MuiTooltip` 을 `surface.overlay` + 테두리로 → 툴팁이 카드와 같은 색이던 문제 해소
- `MuiDivider`·`MuiPaper.outlined` 가 `surface.border` 를 참조

### 팔레트 밖 색 정리

- `SeasonOffDashboard` 카운트다운 카드가 MUI 기본 `green 800`(`#2E7D32`) 그라디언트를
  하드코딩하고 있어 로고 초록과 어긋났다 → `primary.main → primary.dark` 그라디언트로 교체
- `scripts/prerenderStyle.ts` CSS 변수, `index.html` 의 `theme-color` 메타 동기화

## 4. 남은 것

- 지역 허브의 나머지 영역은 여전히 바닥 위 여백이 넓다. 색이 아니라 정보 밀도의 문제라
  다음 패스에서 다룬다
- 라이트 테마는 **구조 정합만** 맞췄다. 미학 재작업은 별도 패스
- 등급 색상은 hue 를 유지한 채 채도만 맞췄다. 1등품 초록(`#69D39E`)이 primary 와
  가까워 범례 없이는 구분이 약하다
- `scripts/prerenderStyle.ts` 의 색 이중 관리는 그대로 (빌드 추출 방식 미결)
