## 1. 목적

1. 날씨(기온·습도·강수·지온)와 공판 물량·등급 분포를 **대조해서 관계를 파악**할 수 있게 한다.
2. 개발자 본인 분석 트랙 + 파워유저(조합 관계자) 탐색 도구. 분석 탐색기의 확장으로 본다.

**하지 않는 것**: 물량·가격·시점의 미래 예측 수치 노출 (10장). 시즌 풍흉 등급 분류·표기 (기준 모호, 2026-09-17 제거 결정).

## 2. 도메인 배경

송이는 기상 조건에 민감하고 **반응에 시차가 있다.**

```
8월 하순~9월 강수  ──(시차)──▶  발생 증가  ──▶  공판 물량 증가
지온 하강 (임계 부근)  ──▶  발생 개시  ──▶  시즌 시작 시점 이동
가을 고온·가뭄 지속  ──▶  발생 부진  ──▶  물량 감소
수확기 강우·고습  ──▶  품질 저하(?)  ──▶  등급 분포 하향(?)
```

- 지온 임계값·시차 일수는 **문헌 확인 전까지 가설값**으로 취급한다 (국립산림과학원 연구 등 조사 예정).
- 관측 가능한 것은 공판 물량·등급·단가. **공판 물량을 발생량의 대리 변수로 쓴다** (한계는 11장).

## 3. 데이터 소스

### 3-1. 기상청 지상(종관, ASOS) 일자료 조회서비스

| 항목 | 내용 |
|---|---|
| 엔드포인트 | `http://apis.data.go.kr/1360000/AsosDalyInfoService/getWthrDataList` |
| 필수 파라미터 | `serviceKey`, `dataCd=ASOS`, `dateCd=DAY`, `startDt`/`endDt` (YYYYMMDD), `stnIds` (지점 1개) |
| 응답 | XML/JSON (`dataType=JSON`), 페이지네이션 `numOfRows`/`pageNo` |
| 갱신 | **전일(D-1) 자료, 당일 11시(KST) 이후 조회 가능** |
| 전송 | http (SSL 없음) → 브라우저 직접 호출 불가, 키 노출 문제도 있음 → **수집 스크립트 전용** |
| 소급 | 지점 관측 개시부터 — 2013~ 전량 확보 가능 |

참고: `SfcYearlyInfoService`(지상기상연보)는 연 1회 갱신·월값 해상도라 부적합. 지점 위경도(`getSfcStnLstTbl`) 확인 용도로만 사용.

### 3-2. 사용 필드

| 필드 | 의미 | 용도 |
|---|---|---|
| `tm` | 일자 | 키 |
| `avgTa` / `minTa` / `maxTa` | 평균·최저·최고 기온 (°C) | 일교차, 늦더위 |
| `sumRn` | 일강수량 (mm) | 누적 강수 (H1·H4) |
| `avgRhm` / `minRhm` | 평균·최소 상대습도 (%) | 등급 분포 (H6) |
| `avgTs` | 평균 지면온도 (°C) | 온도 추세·평년 편차 표시 — 전 지점 (4-4) |
| `avgCm5Te` / `avgCm10Te` / `avgCm20Te` | 5·10·20cm 지중온도 (°C) | H5 임계 시점 — 지중온도 관측 지점만 (4-4) |
| `sumSsHr` | 합계 일조시간 (hr) | 보조 |

결측(`""`, null)은 **0으로 채우지 않는다.** 특히 `sumRn` 빈 값은 "무강수"와 "결측"이 섞일 수 있어 수집 시 원문 보존 후 규칙 확정.

### 4-4. 지중온도 관측 현황 (2026-09-22 테스트 호출, 2025-09-15 기준)

| 구분 | 지점 |
|---|---|
| 5~30cm 지중온도 관측 | 춘천 101 · 북강릉 104 · 강릉 105 · 포항 138 · 청송 276 |
| 미관측 (빈 문자열) | 속초·동해·태백·홍천·인제·봉화·영주·문경·안동·상주·의성·영덕·울진·영천·거창·대구·밀양 |
| 지면온도 `avgTs` | **22개 후보 지점 전부 관측** |

봉화(271)는 2025-09 한 달 30일 모두 지중온도 공백 — 일시 결측이 아니라 미관측 지점.
전 기간 수집(2013~2026) 결과 5개 지점 모두 **14년 연속 관측**, 결측은 연 0~9일 산발.

**대응 (확정)**: 지면온도를 전 지점 대리 지표로 쓰고, 지중온도 관측 5곳에서 **지면온도 ↔ 5cm 지온의 동조성**을 먼저 검증한다.

- 검증: 시즌 창(08~10월) 일별 상관, 하강 추세 시점 차이(일), 임계 통과일 차이
- **판정 기준 (분석 전 고정, 2026-09-22)** — 모두 7일 이동평균 기준, 5개 지점 각각 충족
  | 지표 | 기준 | 이유 |
  |---|---|---|
  | 원값 상관 r | ≥ 0.9 | 계절 하강이 지배하므로 높은 게 당연 — 최소 조건 |
  | **편차 상관 r** (지점·일자별 14년 평년 대비) | **≥ 0.7** | 연도 간 차이를 따라가는지 — 핵심 지표 |
  | 임계 통과일 차이 (5cm 19°C vs 지면온도 19°C+전 지점 공통 오프셋) | 중앙값 \|Δ\| ≤ 3일, 90%가 ≤ 7일 | H5는 시점 가설이므로 |
  - 비교군: 같은 지표를 최저기온·평균기온으로도 계산. 지면온도가 기온보다 낫지 않으면 대리 지표로 기온을 쓴다
  - 19°C는 문헌 확인 전 가설값. 18·20°C에서도 결과가 뒤집히지 않는지 확인
- 통과 시: H5를 지면온도로 전 지점 적용. UI 표기 "지면온도(지온 대리)"
- 미통과 시: H5는 지온 관측 5곳 한정 분석, 나머지 조합은 최저기온 추세로 서술만

**검증 결과 (2026-09-22)** — `scripts/analysis/validate-soil-proxy.ts`, 2013~2025, 08-01~10-31

| 기준 (19°C) | 지면온도 `avgTs` | 평균기온 `avgTa` | 최저기온 `minTa` |
|---|---|---|---|
| 원값 r ≥ 0.9 | ✅ 0.97~0.99 | ✅ 0.98~0.99 | ✅ 0.96~0.98 |
| 편차 r ≥ 0.7 | ✅ **0.76~0.96** | ✅ 0.82~0.91 | ✅ 0.71~0.79 (턱걸이) |
| 통과일 \|Δ\| 중앙값 ≤ 3일 | 4곳 (강릉 4일) | 5곳 | 3곳 (춘천 13일·청송 8일) |
| ≤7일 비율 ≥ 90% | 0곳 (62~77%) | 3곳 | 0곳 |

- 공통 오프셋: 지면온도 +0.59°C, 평균기온 −2.02°C, 최저기온 −5.77°C (5cm 지온 대비)
- 18·20°C에서도 전 지점 통과한 대리 지표 없음 → **임계 통과일 기준은 미통과로 확정**
- 상한 진단: 같은 지점 **10cm 지중온도**로 5cm 통과일을 맞혀도 5곳 중 2곳(북강릉·청송)이 ≤7일 90%에 미달. 첫 통과일은 임계 부근 완만한 하강에서 하루 요동에도 크게 밀리는, 원래 불안정한 지표다. **기준은 사후 완화하지 않는다.**

**결론 — 기준 항목별 적용**

| 용도 | 근거 기준 | 결정 |
|---|---|---|
| V1·V2 온도 추세·평년 대비 편차 표시 | 원값·편차 r | ✅ **지면온도를 전 지점에 사용**. 표기는 "지면온도" 그대로 ("지온" 표기 금지) |
| H5 임계 통과 시점 분석 | 통과일 | ❌ 대리 불가 → **지중온도 관측 지점 한정** (조합 매핑: 강릉·포항·청송) |
| 지중온도 임계선 가이드 (V1) | 통과일 | 지중온도 관측 조합에서만 표시 |
| 미통과 시 대체안 "최저기온 추세" | — | **폐기**. 최저기온은 세 후보 중 가장 약함 |

## 5. 수집 파이프라인

### 5-1. 범위와 호출량

- 기간: 매년 **07-01 ~ 11-30** (시즌 + 시차 분석용 선행 구간)
- 지점: 조합 매핑 18개 + 지온 검증 2개(춘천·북강릉) = **20개**
- 호출: 지점 × 연도 1회 (`numOfRows=200`) → 20 × 14 = **280회** (2026-09-22 백필 완료, 에러 없음)
- 재개: 지점·연도 파일 단위. `complete: false`(진행 중 연도)만 다시 받는다. 호출 한도 초과(22) 시 저장 후 중단

### 5-2. 저장

```
data/weather/                    # 원본 — 분석·재가공용, 번들 제외
  raw/{stationId}/{year}.json    # 보존 필드(KMA_DAILY_FIELDS 17개) 응답 문자열 그대로
public/weather/                  # 클라이언트용 — 시즌 창 집계만
  manifest.json                  # 지점 목록·기간·생성시각
  {stationId}.json               # 전 연도, 3-2 필드만, 지연 로딩
```

- 지점 파일 1개 ≈ 14년 × 153일 × 10필드. gzip 수십 KB 수준 → 조합 선택 시 해당 지점만 로드
- 스크립트: `scripts/collect-weather.ts` (수집, `npm run collect-weather [-- --from YYYY --to YYYY]`), `scripts/generate-weather-stats.ts` (public 가공, 예정)
- 순수 로직(수집 창·URL·응답 해석)은 `src/utils/weather/kmaAsos.ts` — 단위 테스트 대상

### 5-3. 자동화

- 시즌 중 일 1회, **11:30 KST 이후** 실행 (D-1 자료 11시 공개). 기존 `data-collection.yml` 공판 수집 스케줄과 분리된 잡
- API 키: GitHub Secrets `KMA_SERVICE_KEY`, 로컬 `.env`

| H2 | 물량과 단가는 역상관 | 등급별 단가 | 일 공판량 | 일 단위 | 2순위 |
| H3 | 시즌 개시일은 기온 하강 시점과 연동 | 첫 공판일 | 최저기온 | 14 | 탐색용 (H5로 흡수 가능) |
| H4 | 시즌 총량은 8~9월 누적 강수와 상관 | 시즌 총 공판량 | 8~9월 누적 강수 | 14 | 탐색용 |

- 공판일·물량은 **수량 > 0 행 기준** (분석 리워크 Q2·Q3 규칙 동일)
- 시즌 단위 가설(H3·H4)은 표본 14 → 상관계수 제시 금지, 시각화·서술까지만

## 7. 시각화 설계

전부 D3 직접 구현. 게이트(9장) 의존 여부로 두 묶음으로 나눈다.

### 7-1. 게이트 무관 — 사실 표시

**V1. 시즌 오버레이** (핵심 화면)
- 한 조합(또는 지역) × 한 시즌, 공통 날짜축
- 상단: 일 공판량 막대 + 등급 구성 (누적 또는 상위 등급 비율 선)
- 하단: 일강수량 막대 + 기온(최고·최저 밴드) + 지면온도 선 (지중온도 관측 조합은 5cm 지온 선 추가)
- 지온 임계선(가설값, 조정 가능) 가이드 라인 — 지중온도 관측 조합만
- 연도 전환 / **2개 연도 비교** (시즌 일차 정렬 옵션 — 탐색기의 시즌 일차 규칙 재사용)
- 가치: 상관이 약하게 나와도 "그 해 그 무렵 날씨가 어땠나"를 공판과 나란히 보는 것 자체가 목적 1의 절반

**V2. 평년 대비 날씨 스트립**
- 선택 시즌의 강수·기온·지온을 **14년 분포(평년 밴드) 위에** 표시 → "올해 8월 강수는 역대 몇 번째"
- 순위·백분위 서술까지만. 풍흉 판정 문구 금지

### 7-2. 게이트 통과 후 — 관계 서술

**V3. 시차 상관 곡선** (H1·H5): x = 시차 N일, y = 상관계수. 학습 구간/홀드아웃 구간 두 선을 겹쳐 재현성을 함께 표시
**V4. 연도 산점도** (H4): 점 = 시즌, x = 8~9월 누적 강수, y = 시즌 총량. 연도 라벨, **추세선·r 값 없이** 표시 (표본 14)
**V5. 등급 구성 vs 강수·습도** (H6): 일 단위 산점 또는 강수 구간별 상위 등급 비율 분포

### 7-3. 배치 — 미결정 (12장)

- (A) 분석 탐색기(`/data-analysis`)에 기상 레이어·질문 템플릿 추가 — URL 상태·시즌 일차 모델 재사용
- (B) 지역·조합 상세 페이지에 V1 축약 카드
- 권장: **V1·V2는 (A) 본체 + (B) 축약**, V3~V5는 (A)에만

## 8. 진행 순서

```
1. API 키 + 테스트 호출 — ✅ 완료 (09-22). 지중온도 5곳만 관측 → 4-4
        ↓

        ↓
2.5 지면온도 ↔ 5cm 지온 동조성 검증 (4-4) — ✅ 완료 (09-22). 추세 표시 O, 시점 대리 X
        ↓
3. 탐색 스크립트 — H1·H5 시차 스윕, H6 등급 비교        ─┐
        ↓                                                  │ 병행 가능
4. V1·V2 구현 (게이트 무관)                               ─┘
        ↓
5. 게이트 판정 (9장)
        ↓
6. 통과 가설만 V3~V5 구현
```

3에서 신호가 없어도 **4는 유효**하다. 5를 통과하지 못한 가설의 차트는 만들지 않는다.

## 9. 이식 게이트 (v1 유지)

| 조건 | 기준 |
|---|---|
| 상관 강도 | 시차 N에서 \|r\| ≥ 0.3 |
| 유의성 | p < 0.05, 다중 시차 스윕 → 다중비교 보정 |
| 재현성 | **홀드아웃** — 2013~2022로 N 탐색, 2023~2025에서 재현 |
| 설명 가능성 | 도메인 상식·문헌과 크게 어긋나지 않을 것 |

2026 시즌은 종료 후 추가 홀드아웃으로 사용.
