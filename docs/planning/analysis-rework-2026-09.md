## 1. 진단

데스크톱 1440 / 모바일 390, 다크 테마, 시즌 중(2026-09-16) 기본 상태 스크린샷 기준.

### 1-1. 구조 — 고정 대시보드라 질문을 못 바꾼다 🔴

필터 1세트 → 위젯 7개(KPI·리포트·추이·도넛·산점도·지역비교·분포·표)가 **항상 동시에** 렌더된다.
어떤 질문을 하든 같은 7장이 나오고, 질문에 맞는 차트를 고를 수 없다.

표본이 작으면 위젯 대부분이 무의미해진다. 기본값(최근 7일)에서 공판일은 2일뿐이라
점 8개 산점도, 점 1개 지역 비교, 막대 3개 분포가 나온다. 표본 부족 경고도 없다.

### 1-2. 날짜 조회 — 이 데이터에 맞는 시간 축이 없다 🔴

- 입력은 달력 2개 + 프리셋 5개가 전부. **13년 중 어디를 봐야 할지 보여주는 개요가 없다.**
- 송이 데이터의 본질은 "연 1회, 공판일 약 35~65일짜리 시즌 × 14개". 그런데 조회 모델은 달력 기간 하나다.
  - 시즌 개시일이 해마다 **09-01 ~ 09-22로 3주 흔들린다.** 달력 날짜로 겹치면 작황 비교가 왜곡된다.
  - "올해 N일차 vs 역대 N일차", "평년 밴드" 같은 핵심 질문을 표현할 방법이 없다.
- 비교는 기간 2개(주/비교)까지만. 연도 3개 이상을 겹칠 수 없다.
- 상태가 localStorage에만 있다. **URL 공유·북마크·뒤로가기 불가.**

### 1-3. 시인성 🟠

- y축 `1400000원` — 천 단위 구분도, 만원 단위 축약도 없다.
- 점 2개를 곡선 보간 → 존재하지 않는 추이를 그린다. 공판 없는 날도 선으로 이어진다.
- 지역 온보딩 모달이 분석 페이지에서도 뜬다.
- 모바일은 모든 차트가 390px에 압축돼 축 라벨이 겹친다.

### 1-4. 데이터 계층 🟠

- IndexedDB의 숫자 레코드(`AuctionRecord`)를 **문자열 타입(`MushroomAuctionDataRaw`)으로 되돌린 뒤**
  위젯마다 다시 `parseFloat`한다. 불필요한 왕복.
- 기간을 바꿀 때마다 IndexedDB 재조회. 전체가 **16,762행 / 13MB**라 메모리 상주가 훨씬 단순하고 빠르다.

### 1-5. 데이터 품질 — 리워크 전에 확인 필요 ⚠️

| # | 내용 | 영향 |
|---|---|---|
| Q1 | `09-31`(2021~2024)·`11-31`(2021~2023) — **존재하지 않는 날짜** 7개 파일·114행, 전부 금일 공판량 0 | **R0 완료**: 2025-08 과거 데이터 일괄 추가 시 유입. 파일 삭제 + `generate-complete-dataset`에서 `isValidCalendarDate`로 차단 |
| Q2 | ~~2024·2025 공판일 급감~~ → **착시 (정정 2026-09-16)**. 수량 0 행(Q5)이 2023년까지만 있어 날짜 수가 부풀었던 것. 실제 공판일(수량>0)은 2013~2023 33~65일, 2024 43일, 2025 49일로 정상 범위 | 총물량은 2024 69t(하위권), 2025 122t(중간). 흉작 판단은 사용자 도메인 지식 기준으로 `SEASON_NOTES` 유지. **공판일 수는 반드시 수량>0 기준으로 센다** |
| Q3 | 전체 행의 약 60%가 `auctionQuantityToday = 0` (조합별 무공판일 행) | 단가 평균에 0이 섞이면 안 됨. 집계 규칙으로 명시 필요 |
| Q4 | 연도별 참여 조합 변동 (예: 울진 2024 없음, 포항 2021~2023 없음, 영천 2013~2014만) | **확인됨: 실제 공판 없음** (수집 누락 아님). 지역 합산 시 연도 비교에 조합 구성 차이가 섞임 |
| Q5 | 2024년부터 무공판일(수량 0) 행이 거의 없음 (2023: 802행 → 2024: 77행) | 원본 게시 방식 변경 추정. 수량 0 행 제외 규칙이라 집계 영향 없음 |

확인된 정합성: 등급별 수량 합 = 금일 공판량 (6,757행 전부 일치).

## 2. 설계 원칙

1. **질문 → 뷰.** 한 번에 한 질문에 답하는 큰 차트 1개. 위젯 벽 금지.
2. **시즌이 1급 시간 단위.** 달력 기간은 보조. 비시즌 공백은 축에서 접는다.
3. **조회 상태 = URL.** 모든 화면은 링크 하나로 재현 가능해야 한다.
4. **표본을 숨기지 않는다.** n(공판일·레코드)을 항상 표시, 임계 미만이면 경고.
5. **없는 데이터를 그리지 않는다.** 선형 보간만, 무공판일은 끊는다.
6. **숫자는 읽히게.** 단가는 `만원/kg`, 물량은 `kg`/`톤` 자동, tabular-nums.

## 3. 조회 모델

### 3-1. 쿼리 상태 (URL 직렬화)

```ts
type AnalysisQuery = {
  /** 시간 범위: 시즌 선택(연도 다중) 또는 달력 기간 */
  time:
    | { kind: "seasons"; years: number[] }
    | { kind: "range"; start: string; end: string }; // YYYY-MM-DD
  /** 겹침 정렬 기준 */
  align: "calendar" | "seasonDay"; // MM-DD 기준 | 첫 공판일 = 1일차
  regions: string[];
  unions: string[];
  grades: GradeKey[];
  metric: "unitPrice" | "quantity" | "amount" | "cumQuantity" | "gradeShare";
  groupBy: "none" | "year" | "region" | "union" | "grade";
  commonUnitsOnly: boolean; // 공통 조합만 집계
  granularity: "day" | "week" | "season";
  compare: "none" | "normal" | "prevYear"; // 평년 밴드 | 전년
  view: "timeline" | "overlay" | "heatmap" | "coverage" | "rank" | "composition" | "relation" | "table";
};
```

- URL 예: `/data-analysis?view=overlay&years=2026,2025,2023&align=seasonDay&metric=unitPrice&grades=grade1&compare=normal`
- 파싱은 zod 스키마 + 기본값 폴백. 잘못된 파라미터는 무시하고 기본값.
- 기본 상태(파라미터 없음): **시즌 중** → 올해 vs 평년 템플릿 / **비시즌** → 13년 히트맵 템플릿.

### 3-2. 집계 규칙 (순수 함수, 전부 단위 테스트)

| 지표 | 정의 |
|---|---|
| 단가 | **수량 가중 평균** = Σ(수량×단가) / Σ수량. 수량 0 행 제외 |
| 물량 | Σ등급 수량 (kg) |
| 금액 | Σ(수량×단가) |
| 누계 물량 | 시즌 시작부터 해당 일차까지 누적 |
| 등급 비중 | 등급 수량 / 전체 수량 |
| 시즌 일차 | 현재 지역·조합·등급 필터를 적용한 행에서 **연도별 첫 공판일** = 1일차. 쿼리마다 재계산. 축 라벨에 연도별 기준일 표시 |
| 평년 | 선택 연도를 제외한 직전 10개 시즌의 동일 일차(또는 MM-DD) **중앙값**, 밴드는 P25–P75 |
| 주 단위 | 시즌 일차 7일 묶음 (달력 주 아님) |

표본 경고 임계: 공판일 < 5 또는 포인트당 레코드 < 3 → 차트 상단 배지 + 흐림 처리.
상수는 `src/const/Analysis.ts`에 둔다.

## 5. 뷰 명세 (전부 D3 직접 구현)

| 뷰 | 답하는 질문 | 인코딩 | 비고 |
|---|---|---|---|
| **추이** timeline | 이 기간 동안 어떻게 움직였나 | x 날짜(비시즌 접힘 축), y 지표, 선=묶기 차원 | 7일 이동평균 토글, 극값 마커, 크로스헤어 |
| **연도 겹침** overlay | 올해가 예년과 어떻게 다른가 | x 시즌일차/MM-DD, 선=연도, 평년 P25–P75 밴드 | 선택 연도만 강조색, 나머지 회색. 현재 연도 오늘 지점 마커 |
| **히트맵** heatmap | 13년 전체 패턴은 | 행=연도(또는 조합), 열=시즌일차/MM-DD, 색=지표 | 순차 색상, 무공판 셀은 빈칸. 셀 클릭 → 해당 조건으로 추이 뷰 |
| **순위** rank | 어디가 비싸고 많나 | 조합/지역별 가로 막대 또는 dumbbell(비교 기간 대비) | 정렬 토글, 지역 색 도트(`REGION_BASE_HUES`) |
| **구성** composition | 등급 구성이 어떻게 바뀌나 | 100% 누적 영역 (x 날짜 또는 연도) | 등급 색은 기존 고정 팔레트 |
| **관계** relation | 물량과 가격은 연동되나 | 산점도, 점=일×조합 또는 시즌, 색=연도 | 표본 임계 미만이면 뷰 비활성. 추세선 기본 OFF 유지 |
| **표** table | 원본 수치 확인 | 묶기 차원 × 기간 피벗, 정렬, CSV | 모든 뷰의 폴백 |
| **커버리지** coverage | 어느 조합이 언제 데이터가 있나 | 행=조합, 열=연도, 색=공판일 수 | 분석 전 표본 구성 확인용. 셀 클릭 → 해당 조합·시즌 추이 |

공통: 선형 보간만 사용, 무공판일 끊김, y축 만원 단위 포맷, 범례 클릭 토글(기존 기능 이관),
`useContainerSize` 기반 리사이즈.

**공통 조합만 토글**: 연도 겹침·순위(비교)·추이에서 제공. 켜면 선택한 모든 시즌에 공판이 있는 조합만으로 집계. 기본 OFF, 요약 패널에 참여 조합 수 상시 표시.

**시즌 메모**: 흉작·이상기후 시즌은 `src/const/Analysis.ts`의 `SEASON_NOTES`(예: `{ 2024: "역대급 흉작", 2025: "역대급 흉작" }`)로 관리.
시즌 스트립·연도 겹침 범례·히트맵 행 라벨에 표식 + 호버 시 메모 노출. 평년 밴드 해석 오판 방지 목적.

## 6. 질문 템플릿

템플릿 = `AnalysisQuery` 프리셋. 실행 후 사용자가 컨트롤을 바꾸면 템플릿 선택 표시만 해제된다.

| 템플릿 | 세팅 |
|---|---|
| 올해 vs 평년 | overlay · 올해 · seasonDay · 단가 · 1등품 · compare=normal |
| 누계 페이스 | overlay · 올해+최근 5년 · seasonDay · cumQuantity |
| 조합 순위 | rank · 올해(비시즌엔 작년) · 단가 · groupBy=union |
| 등급 구성 | composition · 최근 10년 · granularity=season · gradeShare |
| 13년 한눈에 | heatmap · 전 시즌 · MM-DD · 물량 · groupBy=year |
| 시즌 요약 | table · 전 시즌 · granularity=season (개시일·종료일·피크일·총물량·가중단가) |

기존 `SeasonReport`의 연도별 요약 로직(`utils/analysis/report.ts`)은 "시즌 요약" 표로 흡수한다.

## 8. 데이터 계층

```
IndexedDB(AuctionRecord, 숫자형)
   ↓ 페이지 진입 시 1회 전체 로드
useAnalysisDataset()  — 메모리 상주, 문자열 변환 없음
   ↓ 롱 포맷 파생 1회: { date, year, monthDay, region, union, grade, qty, price }
selectRows(query)     — 필터
aggregate(query)      — 지표·묶기·단위·정렬·평년 계산
   ↓
뷰별 어댑터 → D3 렌더러
```

- 롱 포맷은 약 1만 행 × 6등급 = 최대 6만 행이지만 수량 0 행 제외 시 약 4만. 메인 스레드로 충분.
  집계가 50ms를 넘으면 그때 Web Worker 검토.
- 롱 포맷에는 `seasonDay`를 저장하지 않는다. 시즌 일차는 `selectRows` 이후 필터 결과의 연도별 최소 날짜로 매 쿼리 계산 (M3 결정).
  근거: 전체 첫 공판일은 13년 내내 강원이고 경북은 0~12일, 경남은 더 늦게 개시 → 전체 기준이면 경북·경남 분석 앞쪽에 빈 일차가 생김
- 날짜는 문자열 `YYYY-MM-DD`로만 다룬다. `Date` 객체·`toISOString`은 타임존 오차 위험으로 경계에서만.
