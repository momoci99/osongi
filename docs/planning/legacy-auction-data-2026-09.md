# 옛 공판 데이터(2008~2012) 수집·정합성 기록

작성 2026-09-26 · 브랜치 `feat/legacy-auction-data`

## 원천

- 산림조합 산림경영지원 "송이 공판현황" 게시판 (`board_id=GPB_SONGI`)
- 게시물 254건(seq 1~262, 8개 번호는 삭제됨), 엑셀 첨부 251개. 기간 2008-09-02 ~ 2012-10-19
- 원본은 `data/legacy-auction/raw/` 에 받고 **git 에 올리지 않는다**(권리 미확정, `data-rights-check.md`). 정제 결과만 추적

## 명령

```bash
npm run collect-legacy-auction   # 원본 수집 (이어받기 지원)
npm run refine-legacy-auction    # 정제 + 정합성 보고서
```

산출: `data/legacy-auction/refined/{2008..2012}.json`, `data/legacy-auction/integrity-report.json`

## 서식

집계표 본문은 5년 내내 같은 틀이다: 도별 · 조합별 · 공판량(전일까지/금일/누계) · 공판금액(〃) · 등급 5종(수량/단가).

| 연도 | 시트 구성 | 단가 기준 |
|---|---|---|
| 2008~2009 | 결재 요약 + **당해 집계표** + 전년 비교 집계표 | 등급별 **최고가** (머리글 명시) |
| 2010 | 집계표 1장 (일부 2장) | **평균 단가** — 09-13~10-05 는 문구 없음, 수량×단가 ≈ 금일 금액으로 추정 |
| 2011~2012 | 집계표 1~2장 | 평균 단가 (명시) |

- 옛 서식의 "등외품(혼합품)"은 한 열이라 현행 `gradeBelow` 에 넣었다. 현행 `mixedGrade` 에 대응하는 값은 없다
- **2008~2009 단가는 최고가라 2010년 이후·현행 자료와 바로 비교하면 안 된다.** 정제 자료의 `priceBasis` 로 구분한다

## 정합성 검사 결과

검사 항목과 결과 (2008~2012 원본 250일, 조합 행 약 1,964건 중 금일 공판 있는 행 기준):

| 항목 | 결과 | 판단 |
|---|---|---|
| 전일까지 + 금일 = 누계 | 0건 | 깨끗함 |
| 등급 수량 합 = 금일 공판량 | 0건 | 깨끗함 |
| 평균 단가 × 수량 ≈ 금일 금액 (2010~) | 0건 (±2%) | 깨끗함. 평균 단가 기준 확인 |
| 조합 합 = 도 소계 = 전체 계 | 7건 | 전부 소계·계의 **빈 칸** (2008-10-26, 2009-10-26, 2012-10-07). 값 오류 아님 |
| 전날 누계 = 오늘 전일까지 | 22건 | 누계 소급 정정. 대부분 수 kg·수십만 원. 2008-10-21 은 홍천 +61.01kg·포항 −61.01kg 로 **조합 간 오기재 정정**. 금일 값에는 영향 없음 |
| 등급 수량 있는데 단가 빈 칸 | 1건 | 2008-09-26 울진 등외 13.65kg |
| 머리글 날짜·연도 | 2건 | 2008-09-07 머리글이 "2007", 2009-10-05 제목이 "2008년도". 서식 복사 흔적, 날짜는 게시물 제목 기준 |
| 단가 이상치 (연중 등급 중앙값의 4배 초과·1/4 미만) | 8건 | 금액 ÷ 수량으로 전부 실제 시세 확인(2008 늦시즌 품귀, 2010 초반 인제). 오타 없음 |
| 등급 간 단가 역전 | 321건 | 대부분 3등 생장정지 ↔ 개산품. 시장 현상으로 보고 유지 |

게시판 자체 이상:

- 2008-10-17 게시물이 두 번 올라감(seq 51·52). seq 51 첨부는 깨진 파일 → seq 52 사용
- 2009·2011·2012 시즌 종료 공지는 첨부 없음
- 2012-09-26 제목만 "2012-9-26" 표기

## 전년 비교 시트와 2007년

- 2009 파일의 2008 비교 시트 53장을 2008 원본과 대조: 51장은 "게시물 날짜의 전년 같은 날"과 일치. 머리글 날짜는 두 번(2009-09-25·26 → "2008. 9. 24") 안 고쳐져 있었다. 2009-09-19 비교 시트 한 장은 원본과 다름(강원 고성)
- 원본이 있는 해는 비교 시트를 **대조에만** 쓴다. 채우면 시즌 끝난 날(2008-11-02)이 생긴다
- 2007 은 2008 파일의 비교 시트로만 존재(61일). 누계가 날짜순으로 앞뒤로 흔들려(chain-break 294건) 날짜 배치를 믿을 수 없다 → **정제 자료에서 제외**, 보고서에만 남김

## 결정 (2026-09-26)

1. 2007 비교 시트는 복구하지 않는다 — 실제 날짜를 확정할 수 없어 기상 시차 분석을 오염시킨다
2. 데이터 권리: 문의 후 수개월 회신 없음, 비상업 이용 전제로 사용. **상업적 이용은 하지 않는다**
3. 정제 자료는 git 추적(한 줄 JSON), 원본은 로컬만
